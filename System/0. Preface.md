- 计算机体系结构设计中的8个伟大思想：

  - **面向摩尔定律的设计（Design for Moore's Law）**：单芯片集成度每 18 至 24 个月翻一番；由于芯片设计周期长达数年，设计时必须面向项目完成时的工艺水平进行规划，而非基于设计开始时的现状；
  * **使用抽象简化设计（Use Abstraction to Simplify Design）**：利用分层抽象隐藏底层硬件或实现的细节，在高层呈现简化模型，以此控制系统复杂度并提升软硬件的生产率；
  * **加速大概率事件（Make the Common Case Fast）**：优化频繁发生的操作对系统整体性能的提升远大于优化低频事件；设计者需通过量化实验识别大概率事件并优先优化；
  * **通过并行提高性能（Performance via Parallelism）**：通过在同一时刻并发执行多个操作或指令，突破单任务执行的物理性能瓶颈；
  * **通过流水线提高性能（Performance via Pipelining）**：作为一种重叠执行指令的特定并行机制，将一个完整任务划分为多个连续阶段，使不同指令的不同阶段在时间上重叠运行以提升系统吞吐率；
  * **通过预测提高性能（Performance via Prediction）**：在机制恢复代价较低且预测命中率较高的情况下，通过推测提前执行后续操作，避免因等待确定性结果而产生延迟；
  * **存储器层次（Hierarchy of Memories）**：利用金字塔结构组织存储系统——顶层容量小、速度极快但单比特成本高，底层容量大、速度慢且单比特成本低，从而在整体上实现兼具顶层高速度与底层大容量的效果；
  * **通过冗余提高可靠性（Dependability via Redundancy）**：针对物理器件可能失效的问题，配置备用或重复的冗余部件用于错误检测与故障接管，确保系统在部分硬件损坏时仍能维持可用性；

- 计算机的五大经典部件（冯·诺依曼体系核心）：

  - 输入设备（Input）： 负责将外部数据与程序转换为二进制信息写入存储器；
  - 存储器（Memory）： 存放程序指令和运行所需的数据；
  - 数据通路/运算器（Datapath）： 负责执行算术与逻辑运算，直接处理来自存储器的数据；
  - 控制器（Control）： 指挥协调各部件运行，向数据通路、存储器及 I/O 部件发出控制信号；
    - 处理器（Processor/CPU）： 由控制器与数据通路两部分集成构成；
  - 输出设备（Output）： 从存储器中读取处理结果，转换为外部可见或可记录的形式；

  > 外部支撑与 系统层次：
  > 编译器与接口： 高级语言程序经由编译器翻译为机器指令，通过软硬件接口在计算机上运行；
  > 性能评价： 独立于具体部件之外，用于度量软硬件协同运行时的执行效率与开销；


- 操作系统对底层硬件的抽象作用以及应用二进制接口（Application Binary Interface, ABI）的定义：

  - **操作系统的抽象与封装**：硬件层面直接涉及复杂的底层控制（例如硬件寄存器读写、中断处理、物理页表映射等）；操作系统将 I/O 操作、物理内存管理等低级功能封装起来，向上提供统一的系统服务，使应用程序不需要直接操作裸机硬件；

  - **应用二进制接口（ABI）的构成**：ABI 是二进制程序（已编译的机器码）与底层执行环境（CPU 硬件架构 + 操作系统内核）之间的底层接口规范，主要由两部分构成：
  - **用户态可用的基本指令系统（ISA 子集）**：CPU 允许用户程序在非特权模式下直接执行的机器指令（如算术运算、逻辑运算、分支跳转、寄存器寻址等，排除特权指令）；
  - **操作系统接口**：系统调用规范（System Call Interface），包括系统调用号分配、参数传递方式（通过特定通用寄存器或栈传递）、陷阱指令（如 x86 的 `syscall` / `int 0x80`、RISC-V 的 `ecall`、ARM 的 `svc`）以及返回值约定；

- ABI 涵盖的底层规范细节：

  - 数据类型的二进制表示（大小、内存对齐规则、字节序）；
  - 函数调用约定（Calling Convention）：参数如何通过寄存器与栈传递、返回值存储位置、寄存器保护责任（Caller-saved vs Callee-saved）；
  - 二进制文件格式标准（如 Linux 下的 ELF、Windows 下的 PE）；

- ABI 与 API 的关键区别：

  - **API（应用编程接口）**：面向源代码层级（如 C 语言的 `stdio.h`、POSIX API），只要源码符合 API 规范并在目标平台重新编译，即可实现跨平台移植；

  - **ABI（应用二进制接口）**：面向编译后的机器代码层级；只有当两个系统的 CPU 架构指令集一致，且操作系统内核遵循相同的系统调用与调用约定（即 ABI 兼容），编译出的可执行文件才能无需重新编译直接运行；

### 0. Some Basic Concepts

**Von Neumann Computer Architecture**

1. 计算机由运算器、控制器、存储器、输入设备和输出设备 5 个基本部件组成；

   - CPU = 运算器(数据通路) + 控制器；存储器就是主存；

2. 指令和数据以同等地位存储在存储器中，形式上没有区别，但计算机应能区分它们；

3. 指令和数据均用二进制代码表示；

4. 指令由操作码和操作数组成两部分组成，操作数可以是多个；

5. 采用“存储程序”工作方式；

   > “存储程序” 的基本思想：程序和数据预先存入内存，一旦启动，计算机自动逐条执行指令直至结束，无需人工干预；

---

**硬件系统层级**

- **主机**：CPU + 主存储器，负责核心计算与程序/数据暂存；
- **外设**：I/O 设备，通过 **I/O 总线** 与主机进行双向数据交互；

**CPU 内部组成**

- **运算器**（ALU、GPRs 等）：负责执行算术与逻辑运算；
- **控制器**（CU、PC、IR 等）：负责指令读取、译码及控制信号生成；

**主机三总线（CPU ↔ 主存）**

- **地址总线**：传输主存目标物理地址；
- **数据总线**：双向传输指令与操作数数据；
- **控制总线**：双向传输读写使能、时序及状态反馈信号；

---

**主频的硬件时序本质**

- **时钟周期与主频**：$T = \frac{1}{f}$；
- **时序建立约束**：时钟周期 $T$ 必须大于“触发器建立时间 + 最长组合逻辑延迟 + 时钟偏斜”的总和；
- **物理限制**：主频越高，$T$ 越短，留给每级流水线组合逻辑完成计算与信号建立的时间窗口越小；

**主频与性能的关系**

- **CPU 执行时间模型**：

  $$\text{CPU Time} = \frac{\text{IC} \times \text{CPI}}{f} = \frac{\text{IC}}{\text{IPC} \times f}$$

  - $\text{IC}$（Instruction Count）：程序总指令数；
  - $\text{CPI}$ / $\text{IPC}$：每指令周期数 / 每周期指令数（$\text{IPC} = \frac{1}{\text{CPI}}$）；
  - $f$：运行主频；

- 处理器的实际指令吞吐能力取决于微架构效率与主频的乘积（$\text{IPC} \times f$）；

- 主频仅能作为同代、同微架构 CPU 之间的直接性能参考；跨微架构时高主频常伴随低 IPC（例如深流水线带来的分支预测失败惩罚），无法仅凭主频判断性能优劣；
