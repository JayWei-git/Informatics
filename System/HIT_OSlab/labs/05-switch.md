# 实验五：基于内核栈的切换

## 要学什么

任务切换如何同时改变栈、寄存器和执行流，新任务如何首次运行，TSS 硬件任务切换与软件切换有什么差别；

## 原始文件和步骤

```bash
make prepare LAB=05
cd work/lab05
make lab-test LAB=05
```

补齐 `kernel/runtime.c` 的 `schedule`，原始副本暂时只返回旧现场，不会调度用户任务，目标测试应超时失败；

1. 阅读 `kernel/interrupts.S` 的现场保存布局，与 `struct frame` 逐项核对；保存 frame 指针就是保存该任务的内核栈恢复位置；
2. 保存旧任务现场，必要时从 RUNNING 变为 READY，避免把 WAITING/DEAD 强行放回就绪队列；
3. 轮转选择可运行工作任务，无可运行任务时选择 idle；更新 current、时间片截止 tick 和轨迹；
4. 更新 TSS.ESP0 为新任务内核栈顶，加载相应 CR3；返回新 frame，由汇编切换 ESP、恢复寄存器并 iret；
5. 阅读 `create` 人工构造的新任务栈，解释第一次 iret 与中断返回的关系；

## 验收与思考

三个用户任务都运行并退出，长循环没有主动 yield 也能被时钟抢占；`make runtime-test` 的隔离和信号量案例继续通过；在 GDB 对比两次调度的 frame、ESP、CR3、TSS.ESP0；

本实验不先构建再删除旧式 TSS 任务切换，而是完成软件切换骨架；报告必须分析硬件任务切换保存状态的位置、软件方式的灵活性，以及仍需 TSS 完成 Ring 3→0 栈切换的原因；
