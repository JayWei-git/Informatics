# 实验二：操作系统的引导

## 要学什么

真正观察 BIOS 运行后的 0x7c00 入口、引导扇区搬移、BIOS 磁盘与显示服务、setup、硬件参数和实模式到保护模式的转换；

## 原始文件和步骤

```bash
make prepare LAB=02
cd work/lab02
make bios-test
make bios-run
```

修改 `bios/bootsect.S` 和 `bios/setup.S`；当前初始文件已经能引导，让你在可用代码上修改，与原课从已有 bootsect/setup 开始的方式一致；GNU AT&T 语法替代旧 as86 语法；

1. 把启动提示改为自己的系统名，保持固定测试标记；用 BIOS int 0x10 显示，E9 端口只镜像测试日志，不能用它代替 BIOS 服务；
2. 解释把 256 个字从 0x7c00 拷到 0x90000 的循环，并在 `make bios-debug` 的 0x7c00 断点观测 CS、IP、DL；
3. 跟踪 int 0x13 如何把第 2～5 个扇区读到 0x90200，再远跳转；说明 ES:BX、AH/AL、CH/CL、DH/DL 的含义和 CF 的错误指示；
4. setup 已通过 int 0x12、int 0x15/AH=0x88 读出内存参数；再添加一个显示参数，例如 int 0x10/AH=0x0f 的当前显示模式，打印并保存到自行选择的安全内存；
5. 找到 A20、lgdt、lidt、CR0.PE、远跳转及数据段重载，解释各自作用；
6. 比较实模式内核暂存地址 0x10000 和保护模式目标地址 0x100000；本工程载入内核文件大小上限 64 KiB，超过时构建明确拒绝；

## 验收与思考

日志 `build/bios-test.log` 包含引导、setup、硬件参数和 C 内核启动，屏幕提示有自己的修改；新增参数必须实际来自 BIOS；说明为什么切换后不能直接继续调用 BIOS int 0x13；

测试能证明启动链正常，不会自动判断新增硬件参数是否正确，需提交自己的调试记录；本实验不使用 `make run` 或 GRUB 替代；
