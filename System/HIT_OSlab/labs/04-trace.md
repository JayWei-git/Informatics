# 实验四：进程运行轨迹的跟踪与统计

## 要学什么

进程生命期、调度与阻塞、状态切换的准确位置，利用真实 tick 事件计算等待、运行、阻塞、周转和吞吐量；

## 原始文件和步骤

```bash
make prepare LAB=04
cd work/lab04
make lab-test LAB=04
```

补齐 `kernel/runtime.c` 的 `event`；基线已在创建、切换、阻塞、唤醒、退出处调用它，输出 `TRACE\tpid\tX\ttick`，X 为 N/J/R/W/E；串口接收文件替代原课目标磁盘上的 process.log；

1. 审核所有状态切换点，区分 READY 与 RUNNING；不得把所有就绪变化都当成正在执行；
2. 阅读用户工作负载：三个用户进程各消耗 25 个 CPU tick，其中一个另外睡眠 15 tick；父级基线等待所有任务完成，事件来自实际调度，不由统计脚本生成；
3. 分别以 5 tick、1 tick 时间片运行，保存两份日志；
4. 审核 `tools/trace_stats.py`：累加 J→下一事件的等待、R→下一事件的运行、W→下一事件的阻塞；E-N 为周转，运行+等待+阻塞应等于周转；
5. 修改角色数、CPU 时长和睡眠比例，再比较两种时间片，解释平均数相同或不同的原因；

```bash
make stats
```

会生成 `build/trace-q5.csv`、`build/trace-q1.csv`；当前 PIT 为 100 Hz，一个 tick 为 10 ms；吞吐量是本实验样本进程数除以首个 N 到最后 E 的时间跨度；

## 验收与思考

生命周期无缺失，状态顺序合法；等待进程不能被累计 CPU 时间；说明为什么时间片变化不保证平均指标一定变好；提交两组数据和至少一个改变工作负载后的对比；
