# 原课程与 Arch 新实验的对应

## 设计标准

保留原实验要理解的机制，以及能够证明理解的操作和结果；替换旧工具链、实验宿主和具体代码实现；原课程里的特定内核数据结构不要求逐字复制，但相应概念必须有观测或编程任务；每个实验明确记录简化，不宣称兼容 Linux 0.11 的答案或评分脚本；

| 原实验 | 必须保留的学习内容 | 本工程对应 |
| --- | --- | --- |
| 熟悉环境 | 编译、启动、汇编与 C 调试、宿主和目标系统区别 | 当前 GCC、ELF32、QEMU、GDB |
| 引导 | BIOS 读盘、0x7c00、引导扇区搬移、setup、硬件参数、实模式至保护模式 | 真实软盘镜像、GNU 汇编语法、自己的 GDT 和 A20 操作 |
| 系统调用 | 用户态进入内核、调用号和分发表、参数及用户空间安全、错误返回 | Ring 3、TSS 特权栈、int 0x80、iam/whoami |
| 运行轨迹 | 新建/就绪/运行/阻塞/退出、tick、等待与周转、时间片比较 | N/J/R/W/E 串口事件、CPU/等待混合工作负载、严格生命周期统计 |

## 明确的实现差异

1. 宿主直接是 Arch；内核仍是被 QEMU 模拟的 32 位 x86 程序；当前使用软件模拟，学习不依赖真实 SSD、UEFI 或 CPU 型号；
2. BIOS 路径自行加载内核，不能用 GRUB 或 QEMU 快速入口代替该实验；保留快速入口是为后续实验缩短迭代时间；
3. 原课的 Linux 0.11 使用 LDT 等历史布局；本工程以平坦 GDT 加每进程页目录为主，仍需从段选择子查描述符、计算线性地址、再查页表；不把缺少 LDT 跟踪说成完全相同的实现；
4. 原课把进程日志写入目标磁盘；本工程把内核事件经串口采集到宿主文件，改变的是日志传输，状态切换位置和时间统计仍来自真实虚拟机运行；
5. 切换实验以软件切换的函数骨架为起点，完成缺失部分；不先实现一整套 TSS 硬件任务切换再删除，但必须分析两种机制，并说明为什么 TSS 仍用于 Ring 3→0；
6. 原课的 fork 与父进程等待由基线测试启动器简化为内核创建固定用户任务、idle 等待全部结束；Arch 的 host/pc.c 保留真实 fork、父进程等待和多进程文件缓冲区实践；新内核没有实现 fork，不能据此认为已学完 fork 内部实现；
7. 基线只支持最多 11 个工作任务、8 个命名信号量、key=7 的一个共享页，页资源预留而非动态分配；shmat 的页表修改、TLB 处理和共享效果仍真实发生；
8. 内核生产者消费者复用共享页后端；文件缓冲区与共享映射的比较在 Arch 宿主程序完成；简化了目标内核的普通磁盘文件读写，不省去两类缓冲区的实践；
9. proc 是极小只读文件接口，每进程同时支持一个 proc 描述符，打开时生成快照，读取时维护偏移；不复刻 Minix inode、mknod、完整 VFS 或现代 Linux procfs；实验要求补充节点类型/路径分发设计，比较该简化与完整文件系统；

这些是新的实验设计，不是给旧 Linux 0.11 配一套新编译器；核心机制和对应验证保留，历史细节与工程规模有所调整；

## 学习副本与参考基线

根目录可运行实现用于确认环境和查阅参考；执行 `make prepare LAB=03` 后生成的 `work/lab03/` 才是该实验的初始学习文件；目标函数留 TODO，测试应先失败；先对照任务书完成实现，再运行对应 lab-test；不要仅运行根目录的已完成演示就认为自己完成实验；

每个实验记录：改了哪些函数、为什么改、复现命令、真实日志或寄存器数据、至少一个错误场景；自动测试覆盖固定场景，任务书中的人工调试和分析同样是验收要求；
