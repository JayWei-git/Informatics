# 实验六：信号量的实现与应用

## 要学什么

原子 P/V、等待队列、睡眠与唤醒、多个进程如何共同使用一个信号量，以及生产者消费者为什么需要空槽、产品、互斥三个信号量；

## 原始文件和步骤

```bash
make prepare LAB=06
cd work/lab06
make host-test
make lab-test LAB=06
```

第一部分在 Arch 运行 `host/pc.c`：真实 fork 创建一个生产者、两个消费者，文件后端通过 pread/pwrite 共享容量 10 的缓冲区；父进程等待全部子进程结束并检查 0～999 恰好消费一次；`shared` 后端用 mmap 共享映射作比较；

第二部分补齐 `kernel/runtime.c` 的 `sem_wait`、`sem_post`；命名接口 `sem_named` 已提供，句柄为 1～8；同名打开返回同一对象，不应重复重置初值；

- P：有资源则减少计数；否则把当前任务放入真实等待队列，标记 WAITING，让调用分发器调度；
- V：存在等待者时唤醒一个并把资源交给它，否则增加计数；
- 当前基线用中断门屏蔽中断保护单核临界区，不允许在函数里随意 sti；
- 队列用定长环形数组，不使用哑节点；删除存在等待者的信号量应返回 -16；

## 验收与思考

Arch 文件/映射两种案例及内核用户态案例都消费 1000 个数，和为 499500，无重复、无遗漏、缓冲区不越界；说明为什么等待不能用忙循环代替，为什么先 P(mutex) 再 P(empty/full) 可能死锁；补充同名打开、无效句柄和删除等待中信号量的测试；

内核案例使用共享页缓冲区，普通文件缓冲区的实践在宿主完成；两种后端的差异必须在报告中说明；
